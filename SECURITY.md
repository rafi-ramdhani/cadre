# Security

## Reporting a vulnerability

Please report security problems privately through GitHub's "Report a vulnerability" button on this repository's Security tab, not in a public issue. You should get a reply within a week.

## Things to know

- Persona sessions are full Claude Code sessions. They act on messages from the orchestrator with the permissions of the mode set in `cadre.conf`. A permissive mode such as `auto` lets them act without asking; choose it deliberately.
- The optional orchestrator hook edits `~/.claude/settings.json` (a backup is kept as `settings.json.bak-cadre`).
- `cadre add project`, `cadre sync` and `cadre trust` mark registered project folders as trusted in Claude Code's `~/.claude.json` (the original is kept as `.claude.json.bak-cadre`). Only a project repo's top folder is trusted, never your home, the cadre or a team folder, and persona sessions cannot trust folders. Trust lets a repo's own `.claude/settings.json` take effect, so register only repos you trust; `--no-trust` skips it.
- `cadre uninstall` removes only what the installer created: links that point to this framework, the orchestrator hook in `~/.claude/settings.json` (backup: `settings.json.bak-cadre-uninstall`), `~/.config/cadre/` and the build cache. It never deletes your cadre, projects or framework clone, never revokes trust entries, and cannot run in a persona session.
- Persona sessions get the grants in `<cadre>/.claude/persona-settings.json` through `--settings`, as a read-only copy that the launcher rebuilds from the validated keys at every start (so duplicate keys, edits between the check and the launch, and live edits to the file never reach a persona). The launcher passes it only when it holds nothing but `permissions.allow/deny` and `autoMode.allow/soft_deny` (no `hooks`, `env` or other settings, which a `--settings` file would honour at command-line precedence), keeps `"$defaults"` in every `autoMode` list, and has the entries that deny personas editing it or running `cadre allow`. A hash in `~/.config/cadre/persona-settings.sha256` reveals edits made outside `cadre allow`; the file is committed to your cadre's git.
- `cadre allow` is how consent you give in the orchestrator reaches personas; a cross-session message still never counts as consent. Personas cannot run `cadre allow add` or `remove` (refused when `CADRE_PERSONA` is set), the settings file denies editing itself and running `cadre allow`, its `soft_deny` entry tells the auto-mode classifier that changing persona permissions is the user's job, the hash reveals edits made outside `cadre allow`, and every change is committed. Blanket rules are refused. Known limits: a persona in a permissive mode with shell access could still try to edit files in the cadre folder; these layers make that explicit and visible rather than silent, and the permission mode remains the real boundary. A one-time grant is usable by any persona, any number of times, until it is removed.
- `install.sh` is meant to be read before you pipe it to bash. It writes only to the cadre folder you name, `~/.local/bin/cadre`, `~/.claude/skills/cadre`, `~/.config/cadre/` and, with the hook, `~/.claude/settings.json`.
