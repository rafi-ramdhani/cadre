# Task 0 checklist: verify Claude Code behaviour for 0.2.0

Manual checks T0-1 to T0-4 from `0.2.0-update-allow-trust.md`, as copy-paste steps. About 15 minutes. Everything runs in a scratch folder with its own Claude Code config, so your real `~/.claude.json` and `~/.claude/settings.json` are not touched.

Use two terminals, A (Claude Code) and B (edits). Paste the setup block into both. Record each **Record** line in the results block at the end.

## Setup (both terminals)

```bash
export T=/tmp/cadre-t0
export CLAUDE_CONFIG_DIR=$T/cfg
mkdir -p $T/cfg $T/work && cd $T/work
# Show the trust entries in the scratch config.
keys() { python3 -c 'import json,os; d=json.load(open(os.environ["CLAUDE_CONFIG_DIR"]+"/.claude.json")); [print(k, v.get("hasTrustDialogAccepted")) for k, v in d.get("projects", {}).items()]'; }
# Add a trust entry by hand (only while no claude session is running).
trust() { python3 - "$1" <<'PY'
import json, os, sys
f = os.environ["CLAUDE_CONFIG_DIR"] + "/.claude.json"
d = json.load(open(f))
d.setdefault("projects", {})[sys.argv[1]] = {"hasTrustDialogAccepted": True}
json.dump(d, open(f, "w"), indent=2)
PY
}
```

In terminal A only, once: run `claude`, log in with `/login`, accept the trust prompt for `/tmp/cadre-t0/work`, then `/exit`. Then run `claude --version`.

**Record:** the Claude Code version.

## T0-1. Is a `--settings` file live-reloaded?

`touch` in the working folder is auto-allowed and never prompts, so the probe is `ln -s x probe-1`.

1. B: `echo '{"permissions":{"allow":[]}}' > $T/probe.json`
2. A: `claude --permission-mode default --settings $T/probe.json`
3. A, in the session: `Run exactly this bash command and nothing else: ln -s x probe-1`. A permission prompt should appear. Answer **No**.
4. B: `echo '{"permissions":{"allow":["Bash(ln -s x probe-1)"]}}' > $T/probe.json`, then wait 10 seconds.
5. A: send the same request again.
   **Record (add):** prompt or no prompt. No prompt means additions are live.
   If it prompted: answer No, `/exit`, start again with the command from step 2, and repeat the request. **Record:** prompt or no prompt after a restart (expected: none, which shows the rule itself is right).
6. B: `rm -f probe-1; echo '{"permissions":{"allow":[]}}' > $T/probe.json`, then wait 10 seconds.
7. A: send the same request again.
   **Record (remove):** prompt or no prompt. A prompt means removals are live. Answer No, then `/exit`.
8. autoMode entries. Make a local repo whose push to `main` the classifier is likely to question:

   ```bash
   # B
   git init -q --bare $T/remote.git && git init -q -b main $T/work/repo
   git -C $T/work/repo commit -q --allow-empty -m init && git -C $T/work/repo remote add origin $T/remote.git
   echo '{"autoMode":{"allow":["$defaults"]}}' > $T/probe.json
   ```

   A: `claude --permission-mode auto --settings $T/probe.json`, then `Run exactly: git -C /tmp/cadre-t0/work/repo push origin HEAD:main`.
   **Record:** allowed, blocked by the classifier, or prompted. If it was allowed, this probe cannot show the reload; record that and skip to step 9.
9. B: `echo '{"autoMode":{"allow":["$defaults","Pushing to main in the scratch repo /tmp/cadre-t0/work/repo is expected"]}}' > $T/probe.json`, then wait 10 seconds.
   A: send the same request again.
   **Record (autoMode add):** allowed or blocked. Allowed means autoMode entries are live. If blocked, `/exit`, start again with the same command and retry. **Record:** allowed or blocked after a restart. Then `/exit`.
10. Missing file. A: `claude --settings $T/does-not-exist.json`.
    **Record:** starts normally, starts with a warning (copy it), or refuses to start. Then `/exit`.

## T0-2. Is `.claude/` a protected path in auto mode?

1. B: `mkdir -p $T/work/.claude && echo '{}' > $T/work/.claude/persona-settings.json`
2. A: `claude --permission-mode auto`, then `Use the Write tool to replace .claude/persona-settings.json with {"permissions":{"allow":["Bash(*)"]}}`.
   **Record:** prompted, blocked (copy the reason), or written silently. Check with `cat $T/work/.claude/persona-settings.json` in B.
3. For comparison, the same file outside `.claude/`. B: `echo '{}' > $T/work/persona-settings.json`. A: `Use the Write tool to replace persona-settings.json with {"permissions":{"allow":["Bash(*)"]}}`.
   **Record:** prompted, blocked or written silently. Then `/exit`.

## T0-3. Trust key form

`/tmp` is a symlink to `/private/tmp` on macOS, so `$T` is itself a symlinked path. On Linux, steps that compare the two forms use `$T/link` instead.

1. B: `mkdir -p $T/real/a $T/real/b $T/real/c $T/real/d $T/real/e $T/parent/child && ln -sfn $T/real $T/link`
2. Key Claude Code writes itself. A: `cd $T/real/a && claude`, accept the trust prompt, `/exit`. Then `keys`.
   **Record:** the exact key for `a` (`/tmp/...` or `/private/tmp/...`, any trailing slash).
3. Is a minimal entry enough, and which form counts? No claude session may be running for this step. B:

   ```bash
   P=$(cd $T/real && pwd -P)
   trust "$P/b"            # physical path
   trust "$T/real/c"       # path as typed (through /tmp)
   trust "$P/d/"           # trailing slash
   trust "$P/e"            # physical path, entered below through the symlink $T/link
   ```

   A, for each folder in turn, start and look for the trust prompt, then `/exit` (answer **No** or press Esc if it prompts):
   `cd $T/real/b && claude`, `cd $T/real/c && claude`, `cd $T/real/d && claude`, `cd $T/link/e && claude`.
   **Record:** prompt or no prompt for b, c, d and e. Run `keys` afterwards and **record** any new keys Claude Code added.
4. Parent inheritance. A: `cd $T/parent && claude`, accept the prompt, `/exit`. Then `cd $T/parent/child && claude`.
   **Record:** prompt or no prompt in `child`. Then `/exit`.
5. Does a running session overwrite an outside change? A: `cd $T/work && claude` and leave it running. B: `mkdir -p $T/real/f && trust "$(cd $T/real && pwd -P)/f"`. A: send `hello`, wait for the reply, `/exit`. B: `keys`.
   **Record:** is the entry for `f` still there?

Also record where the config lives: with `CLAUDE_CONFIG_DIR` set, check that `$CLAUDE_CONFIG_DIR/.claude.json` changed during these steps and `~/.claude.json` did not (`ls -l ~/.claude.json` before and after).

## T0-4. Unknown keys and self-modification

1. B: write the file in the shape the spec uses, plus one unknown key:

   ```bash
   cat > $T/persona.json <<'JSON'
   {
     "permissions": {
       "allow": ["Bash(ln -s x probe-1)"],
       "deny": ["Edit(/tmp/cadre-t0/persona.json)", "Write(/tmp/cadre-t0/persona.json)", "Bash(cadre allow:*)"]
     },
     "autoMode": {
       "allow": ["$defaults"],
       "soft_deny": ["$defaults", "Changing persona permissions (editing /tmp/cadre-t0/persona.json or running cadre allow) is only done by the user through the orchestrator"]
     },
     "cadreUnknownKey": 1
   }
   JSON
   ```

2. A: `cd $T/work && claude --permission-mode auto --settings $T/persona.json`. Look at the startup screen, then run `/doctor` and `/status`.
   **Record:** any warning about the file or the unknown key (copy it), and whether `/status` lists the file as a settings source.
3. A: `Run exactly: ln -s x probe-1` (B: `rm -f $T/work/probe-1` first if it exists).
   **Record:** ran without prompt (the file loaded despite the unknown key) or prompted.
4. Self-modification without the deny rules. B: remove the `deny` list and the `soft_deny` entry:
   `echo '{"permissions":{"allow":[]},"autoMode":{"allow":["$defaults"]}}' > $T/persona.json`, then in A `/exit` and start again with the command from step 2.
   A: `Use the Write tool to add "Bash(rm:*)" to permissions.allow in /tmp/cadre-t0/persona.json`.
   **Record:** prompted, blocked by the classifier (copy the reason), or written silently. This shows whether the built-in defaults already block self-modification.
