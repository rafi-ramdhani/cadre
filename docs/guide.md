# Cadre guide

## Concepts

| Term | What it is |
|---|---|
| **Cadre** | Your folder, generated by `install.sh` or `cadre init`. Holds the playbook, registry, personas and projects. Its own git repo. |
| **Framework** | This repo. The `cadre` command, the shared protocol, the orchestrator skill, the template. Lives in your cadre at `projects/cadre`. |
| **Orchestrator** | The Claude Code session you talk to. It follows the `cadre` skill and your playbook, and never does a persona's job itself. |
| **Persona** | A Claude Code session with a role, started from `personas/<team>/<role>.md`. |
| **Team** | A folder of personas. Started together or one at a time. |
| **Project** | A git repo listed in `projects.yaml` and cloned into `projects/<name>`. |

## Writing a persona

`cadre add persona ops/sre` creates a stub. A good persona file is short and concrete:

```markdown
# Persona: Site Reliability Engineer (ops team)

You are the SRE. You keep the services up and explain what broke.

- Read the logs and metrics before you form a theory.
- Change production only when the orchestrator's task says so.
- In your reply: what you found, what you changed, how you verified it.
```

Guidelines:

- **One role, plainly stated.** What the persona owns and what it does not do.
- **How to work**, in a few bullets. Concrete habits beat adjectives.
- **What the reply contains.** The orchestrator relays it, so make it easy to relay.
- Leave out reply mechanics; the shared protocol (`protocol.md`) already covers them.

### Working folders

- A persona started for a project (`cadre up dev my-app`) works in `projects/my-app`.
- A team without a project works in `teams/<team>/`, unless `personas/<team>/.workdir` names another folder.
- `personas/<team>/<role>.workdir` pins one persona to its own folder. Useful for a tutor per study track, each in its own directory.

A `.workdir` file holds one path; `~` is expanded.

## The playbook

`playbook.md` is read by the orchestrator at the start of every session and wins over the generic skill where they differ. Put there:

- **Teams**: who exists and what each team is for.
- **Pipelines**: multi-step flows, for example *pm, then engineer, then reviewer, then engineer fixes*.
- **Routing rules**: which requests go where, and anything the orchestrator must never do itself.
- **Project notes** that do not fit the registry, such as how deploys work.

Keep it the single source of truth for routing. When a rule changes, change it here.

## House rules

`protocol.md` in your cadre (optional) is appended to the framework's protocol for every persona. Use it for rules that apply to all personas, for example a writing style.

## The registry

`projects.yaml` is a flat list:

```yaml
my-app:
  repo: you/my-app        # owner/repo, a git URL, or a local path
  team: dev               # the team that usually handles it
  about: The main product # one line for the orchestrator
  path: ~/elsewhere/app   # optional; default is projects/my-app
```

`cadre add project` appends an entry, clones the repo and commits the change. `cadre sync` clones every entry that is missing locally.

## The orchestrator hook

`install.sh --orchestrator-default` adds a SessionStart hook to `~/.claude/settings.json` that tells every new session to act as the orchestrator. It stays silent in persona sessions (the launcher sets `CADRE_PERSONA`) and in sessions started with `CADRE_OFF=1 claude`. Without the hook, ask any session to use the cadre skill.

To remove it, delete the SessionStart entry whose command ends in `orchestrator-hook.sh`.

## Configuration

`cadre.conf` is sourced by the launcher:

| Setting | Default | Meaning |
|---|---|---|
| `PERMISSION_MODE` | `default` | Permission mode for persona sessions |

Environment variables: `CADRE_HOME` (use another cadre for one command), `CADRE_PERMISSION_MODE` (override the mode), `CADRE_REPO` (where the installer fetches the framework), `CADRE_TMUX_SOCKET` (run sessions on a separate tmux server).

## Troubleshooting

- **A persona never replies.** Attach (`cadre attach <team> [project]`) and look. A new folder shows Claude Code's trust prompt on first launch; accept it once.
- **Messages wait for approval.** The persona runs in a different permission-mode class from the orchestrator. Align `PERMISSION_MODE` with the mode you run the orchestrator in.
- **`cadre: no active cadre`.** Run `cadre use <your cadre folder>`.
- **Moved the framework.** Run `projects/cadre/install.sh --link-only` to relink.
